You ask Claude Code for a program that uses Claude: an email sorter, a support chatbot, a tool that reads
invoices. With the Tokyn plugin, Claude writes it in **Tokyn**, where agents, tools and structured answers are part
of the language, so it writes far less code. The compiler checks it, Claude tries it with real answers through your
own Claude Code, and you get a normal Python file.

## Install in Claude Code

```text
/plugin install tokyn-en --marketplace DamianoCeka/tokyn
```

On Claude Code older than 2.1.275, use two commands: `/plugin marketplace add DamianoCeka/tokyn`, then
`/plugin install tokyn-en@tokyn`. The Italian Skill is `tokyn@tokyn`. The plugin ships the compiler and everything it
needs: you only need Python 3.10 or newer.

## How you use it

Ask for the program as usual and add *"use tokyn"*, or call the Skill with `/tokyn-en:tokyn`. Claude:

1. **writes the program in Tokyn**;
2. **checks it and runs it for free** with fake answers (`--mock`), fixing the errors the compiler explains line by
   line;
3. **runs it with real answers** through your Claude Code while you develop it, with no API key;
4. **hands you the Python file**, generated by the compiler with `tokyn build --standalone`. The model does not write
   that code, so it costs no tokens.

## What a Tokyn program looks like

```
type Ticket:
    category: "technical" | "sales" | "other"
    urgent: bool "True if the customer is blocked"

def search_faq(question: str) -> str:
    """Searches the company FAQ."""
    return read_file("faq.txt", "")

agent Support:
    instructions: "Answer customers briefly and politely."
    tools: [search_faq]
    output: Ticket

main:
    t = Support.ask(input("How can I help? "))
    if t.category == "technical" and t.urgent:
        print("Passing you to an operator right away.")
```

In Python the same program needs the API client, the tool-call loop, the JSON schema, parsing and validating the
answer, and retries. In Tokyn all of that is inside `Support.ask(...)`. Ordinary logic is not shorter than in
Python: the saving is in the part that talks to the model.

When something is wrong, the compiler says exactly what to fix, so the AI fixes it by itself:

```
support.tokyn:11:25 error E133: the tool "book_apointment" does not exist
  11 |     tools: [search_faq, book_apointment]
     |                         ^^^^^^^^^^^^^^^
     → Did you mean "book_appointment"? Available tools: book_appointment, search_faq
```

## The numbers

**All the benchmarks were run with Anthropic's Claude** (Claude Code with Opus 5.5 and Sonnet 5.5). Tokyn also works
with other providers (see below), but we have not measured them.

**The method.** 15 requests for Python programs that use Claude, sent to Claude Code in three ways:

- **with Tokyn**;
- **plain Python**, as Claude Code writes it by default;
- **Python with the Claude Agent SDK**, which can also be tried without an API key, through Claude Code.

Each request ran 3 times on each model: 270 fresh sessions in a clean folder, with no API key, as for someone who uses
Claude Code on a subscription. Every delivered `programma.py` was then run on hidden data and checked automatically.

The tasks, checks, scripts and analysis were [published before the runs](https://github.com/DamianoCeka/tokyn/commit/80ccedb).
Full results, method and limits are in [`bench/claude-code/v2/`](bench/claude-code/v2).

| | Opus 5.5 | Sonnet 5.5 |
|---|---:|---:|
| **Cost, Tokyn vs plain Python** | **−68%** (95% CI −71% to −66%) | **−68%** (−71% to −65%) |
| **Cost, Tokyn vs Python + Agent SDK** | **−61%** (−68% to −51%) | **−70%** (−72% to −68%) |
| Output tokens, Tokyn vs plain Python | −56% | −52% |
| Time, Tokyn vs plain Python | −23% | ±0% |
| Passed the hidden tests: Tokyn / plain Python / Agent SDK | 45 · 0 · 45 of 45 | 44 · 0 · 45 of 45 |
| Cost of one run of the delivered program: Tokyn / Agent SDK | $0.008 / $0.036 | $0.008 / $0.037 |

**What the numbers mean, and what they don't:**

- **Where the saving comes from.** Without Tokyn, Claude almost always opens Claude Code's built-in `claude-api` Skill
  to study the Anthropic API: 90 sessions of 90 with plain Python, 73 of 90 with the Agent SDK. That costs a lot of
  tokens. The few Agent SDK sessions that skipped it cost about as much as Tokyn.
- **Time is not a clear win.** Tokyn tries the program with real answers, and that takes time: faster with Opus, the
  same or a little slower with Sonnet.
- **Plain Python could not run.** Without an API key, the program Claude wrote stopped at authentication in all 90
  runs. With a key, Claude would have tested it, spending more turns and tokens.
- **Tokyn loses where there is little AI.** On the web-server-log task, mostly ordinary code, the Agent SDK was
  cheaper with Opus. Tokyn also failed one hidden test (a sales report with Sonnet).
- **The tasks were designed by Tokyn's author**, with Claude agents and an independent review for bias. Costs are list
  prices as reported by Claude Code.

An earlier, smaller benchmark counted code tokens with an old tokenizer: it is kept in [`bench/`](bench) for history
only. The [`eval/`](eval) rounds show that Opus, Sonnet and Haiku write Tokyn after reading only the Skill: 80 of 80
programs compiled and ran in mock mode at the first attempt.

## Who answers the agents

When the program runs, every `Agent.ask(...)` is a request to a model. Tokyn picks who answers.

**Your Claude Code, for trying your own programs.** If there is no `ANTHROPIC_API_KEY` and `claude` is installed, each
request is a `claude -p` call with your login. Tokyn prints a notice the first time.

Anthropic's [rules for Claude Code](https://code.claude.com/docs/en/legal-and-compliance) say that a subscription is
for ordinary, individual use: a product, or a program other people use, must use an API key.

**The Anthropic API, with `ANTHROPIC_API_KEY`**, for programs that run on their own or serve other people. Here the
runtime saves on its own:

- prompt caching;
- native structured outputs;
- `Agent.ask_all(texts)` on the Batch API at half price;
- `effort: "low"` for agents that classify or extract.

**Other providers.** Write `model: "openai:gpt-5.6-luna"`, `"gemini:gemini-3.8-flash"`, `"mistral:..."`,
`"deepseek:..."`, `"groq:..."`, `"openrouter:..."`, `"xai:..."`, `"ollama:qwen3.8"` (a free local model), or
`"openai-compatible:..."` for any compatible server. Each one uses its own key, for example `OPENAI_API_KEY`.

- Tools, structured outputs, memory and retries work as with Claude.
- This adapter is tested against a fake server, not yet against the real services.
- Trying programs without a key works only with Claude, through Claude Code, or with Ollama on your computer.

`tokyn run file.tokyn --backend claude-code` (or `api`) forces the choice, and `--usage` prints the tokens spent.

## How it compares

| | Tokyn | [BAML](https://github.com/BoundaryML/baml) | [Pydantic AI](https://github.com/pydantic/pydantic-ai) | Anthropic Python SDK | Claude Agent SDK |
|---|---|---|---|---|---|
| **What you write** | `.tokyn` (Python syntax) | `.baml` files | Python | Python | Python |
| **What you ship** | One Python file. It needs `anthropic` or the `claude` CLI, or plain HTTP for other providers | Generated Python/TypeScript clients, or a binary | Python | Python | Python |
| **Structured output** | `type` + `output:` | Classes; a parser that corrects the model's text | `output_type=PydanticModel` | `messages.parse(...)` | JSON schema, which you validate yourself |
| **Models** | Claude; OpenAI-compatible providers | Many | About 30 providers | Claude only | Claude only |
| **Check before running** | Compiler with 63 error codes and fixes; `--mock` | Compiler, editor extension, `baml test` | Type checkers; `TestModel` for runs without a model | Type checkers | Type checkers |
| **Made for Claude Code to write** | Yes: Skill, errors that tell the fix | Yes: `baml agent install` adds a skill | No | Its docs are a built-in Claude Code Skill | No |
| **Maturity** | New (0.1) | About 9.5k stars, public beta of v1 | About 20.9k stars | Official | Official |

Stars as of 2026-10-29. Pydantic AI and BAML are more mature and support more providers. Tokyn's bet is narrower: the
cheapest way for Claude Code to write, check and try a program that uses Claude.

## FAQ

**Why a language and not a library?** A library still asks the model to write the glue code and to know its API.
Tokyn makes the declarations the whole program, and its compiler can explain errors to Claude in terms of those
declarations. A good framework like Pydantic AI gets close in code length; the difference in the benchmark comes from
the session as a whole.

**The model has never seen Tokyn: doesn't it make mistakes?** The syntax is Python's, and the Skill (about 3,000
tokens for the English one) teaches the rest, and the compiler explains any mistake before the program runs. In the
benchmark, Claude used the Skill in every Tokyn session and 89 of 90 programs passed the hidden tests.

**Am I locked in?** No. `tokyn build --standalone` gives you a plain Python file you can keep and edit without Tokyn.

**Does Tokyn send data anywhere?** The compiler runs locally. Agents call the model you choose (your Claude Code, the
Anthropic API or the provider in `model`), and your program calls the URLs it uses. There is no telemetry.

## The language in short

- **`agent`**: model, instructions, tools, memory, structured output, `effort`. Use it with `Agent.ask(text)` or,
  for many texts, `Agent.ask_all(texts)`.
- **`def`**: ordinary functions. They become tools when you list them in an agent's `tools`, and the arguments coming
  from the AI are type-checked.
- **`type`**: structured data, nested too, with allowed values (`"a" | "b"`) and descriptions for the AI.
- **Agents as tools**: an agent can delegate to another one.
- **Python everywhere**: `import` any library, slices, f-strings, string, list and dict methods.
- **Fallback values instead of `try`**: `read_file(p, "")`, `http_get(url, "")` and `to_number(text, 0)` don't stop the
  program when the file is missing, the network fails or the number is invalid.
- **Errors designed for the AI**, in English or Italian: on the line of the `.tokyn` file, with the fix. If a model
  writes a comprehension, `a if c else b` or `is None` out of habit, the compiler says what to write instead.

The full specification is [`tokyn/SPEC.en.md`](tokyn/SPEC.en.md), and there are examples in [`examples/`](examples).

## From the terminal

```bash
pip install git+https://github.com/DamianoCeka/tokyn
```

```bash
tokyn new first                       # creates first.tokyn
tokyn check first.tokyn               # checks it and explains the errors
tokyn run first.tokyn --mock          # runs it without calling the AI (free)
tokyn run first.tokyn --usage         # runs it for real (Claude Code or an API key)
tokyn build first.tokyn --standalone  # writes a Python file that doesn't need Tokyn
tokyn spec                            # prints the specification
```

Messages are in English or Italian: `--lang en|it` or `TOKYN_LANG`.

## How it works

```
file.tokyn → parser (Lark) → checker (types, names, agents) → generator → Python → runtime (Claude or other providers)
```

- `tokyn/grammar.lark`: the grammar
- `tokyn/checker.py`: the checks and the error messages
- `tokyn/codegen.py`: the translation to Python
- `tokyn/runtime.py`: agents, tool loop, validation, Anthropic API, Claude Code, other providers
- `plugins/`: the Claude Code plugins; `scripts/build_skill.py` copies the compiler into them

The charts on this page are generated from the data with `python scripts/make_charts.py`.
